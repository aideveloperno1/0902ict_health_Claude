# 운동 일지 API (Workout Log API)

헬스 **운동**과 **식단**을 기록하고 관리하는 REST API 서버입니다.
회원가입 후 로그인하면 토큰이 발급되고, **내가 쓴 기록만** 보고 쓰고 지울 수 있습니다.

> 학습용 프로젝트입니다. 데이터는 **MongoDB에 저장되므로 서버를 껐다 켜도 그대로 남아 있습니다.**

## 1. 무엇을 할 수 있나요

| 기능 | 설명 |
|---|---|
| 회원가입 | 이메일 · 비밀번호 · 이름으로 계정을 만듭니다 |
| 로그인 | 토큰(JWT)을 받습니다. 이후 요청에 이 토큰을 넣습니다 |
| 로그인 유지 | 새로고침해도, 며칠 뒤에 다시 와도 로그인이 유지됩니다 |
| 비밀번호 변경 | 프로필에서 바꿉니다. 다른 기기의 로그인은 모두 풀립니다 |
| 화면 밝기 | 밝은 화면 · 어두운 화면 · 시스템 설정 따르기 중에 고릅니다 |
| 일지 쓰기 | 날짜 · 제목 · 운동 시간 · 운동별 세트(무게·횟수·완료)를 기록합니다 |
| 일지 목록 | 내가 쓴 일지를 최신 날짜순으로 봅니다 (10건씩 나눠 보기) |
| 일지 상세 | 운동별 세트와 볼륨을 자세히 봅니다 |
| 볼륨 자동 계산 | 무게 × 횟수로 세트·운동·일지 볼륨을 합산합니다 (완료한 세트만) |
| 일지 수정 | 기록한 내용을 고칩니다 |
| 일지 삭제 | 내 일지를 지웁니다 |
| 식단 기록 | 끼니(아침·점심·저녁·간식)별로 음식과 영양 정보를 남깁니다 |
| 일일 영양 결산 | 날짜별로 묶어 총 칼로리와 탄·단·지 비율을 보여줍니다 |
| 신체 지표 | 날짜별 체중과 컨디션 메모를 남깁니다 (하루 1건) |
| 프로필 | 성별·출생연도·키를 저장합니다 (기초대사량 계산용) |
| 통합 대시보드 | 날짜 하나를 골라 그날의 운동·식단·신체 기록과 칼로리 밸런스를 봅니다 |
| 루틴 템플릿 | 자주 하는 운동 구성을 저장해 두고 일지를 쓸 때 그대로 불러옵니다 |
| 직전 기록 불러오기 | 같은 운동 이름의 가장 최근 무게·횟수를 폼에 채웁니다 |

**남의 기록은 보이지도 않고 지울 수도 없습니다.** 다른 사람의 번호로 요청하면 "없다"(404)고 응답합니다.

## 2. 준비물

**Node.js 18 이상**과 **MongoDB**가 필요합니다.

**Node.js 확인**

```bash
node -v
```

`v18.0.0` 같은 버전이 나오면 됩니다. `command not found`가 나오면 [nodejs.org](https://nodejs.org)에서 LTS 버전을 설치하세요.

**MongoDB 확인** (Windows PowerShell)

```powershell
Get-Service MongoDB
```

`Running` 이면 됩니다. 없거나 멈춰 있으면 아래 3장에서 설치·시작합니다.

## 3. 설치하기

### ① MongoDB 설치

데이터를 저장할 곳입니다. 계정 가입이나 인터넷 연결은 필요 없습니다.

```powershell
winget install MongoDB.Server
```

winget이 없으면 [mongodb.com/try/download/community](https://www.mongodb.com/try/download/community) 에서 MSI를 받아 설치하세요.
설치 중 **"Install MongoDB as a Service"** 를 켜 두면 컴퓨터를 켤 때 자동으로 실행됩니다.

```powershell
Get-Service MongoDB      # Running 이어야 합니다
Start-Service MongoDB    # 멈춰 있으면 시작
```

### ② 패키지 설치

```bash
cd workout-log-api
npm install
```

### ③ 환경 변수

`.env.example`을 복사해서 `.env`로 이름을 바꾸면 됩니다.

```bash
# macOS / Linux / Git Bash
cp .env.example .env

# Windows PowerShell
Copy-Item .env.example .env
```

만든 `.env` 파일을 열어 `JWT_SECRET` 값을 아무 문자열로 채웁니다.

```
PORT=3000
JWT_SECRET=my-super-secret-key-change-me
MONGODB_URI=mongodb://127.0.0.1:27017/workout-log
DB_DEBUG=false
```

> `JWT_SECRET`은 토큰에 서명할 때 쓰는 비밀 키입니다. 아무 값이나 넣어도 동작하지만, **비워 두면 서버가 켜지지 않습니다.**
> 기본값을 두지 않는 이유는, 코드에 적힌 기본 키는 누구나 볼 수 있어서 그 키를 아는 사람이 남의 토큰을 마음대로 만들어 낼 수 있기 때문입니다.
> 이 값을 바꾸면 **이전에 발급된 토큰은 모두 무효**가 되어 다시 로그인해야 합니다.
>
> `DB_DEBUG=true`로 두면 MongoDB에 실제로 보내는 쿼리가 터미널에 그대로 찍힙니다.
> 내가 짠 조건이 어떤 쿼리가 되는지 확인할 때만 잠깐 켜세요. 평소에는 로그가 너무 많아 불편합니다.
>
> `MONGODB_URI`는 로컬 주소라 비밀번호가 없습니다. `.env.example`에 적힌 값을 그대로 쓰면 됩니다.
> `workout-log` 데이터베이스는 **처음 저장할 때 자동으로 만들어집니다.** 미리 만들 필요가 없습니다.
>
> `.env`는 `.gitignore`에 등록되어 있어 깃에 올라가지 않습니다.

## 5. 화면으로 사용하기

서버를 켠 뒤 브라우저에서 **<http://localhost:3000>** 에 접속하면 됩니다.
설치할 것도, 따로 띄울 서버도 없습니다. API 서버가 화면까지 같이 내보냅니다.

```
1. 회원가입     이름 · 이메일 · 비밀번호(8자 이상)를 넣고 [회원가입]
                → 가입되면 자동으로 로그인됩니다
                ↓
2. 일지 쓰기    [+ 새 일지 쓰기] → 날짜는 오늘로 채워져 있습니다
                운동마다 이름과 부위(가슴/등/하체/어깨/팔/복근)를 고르고,
                [+ 세트 추가]로 세트를 쌓습니다
                → 새 세트는 직전 세트의 무게·횟수가 그대로 채워집니다
                → 완료에 체크하면 볼륨(무게×횟수)이 즉시 합산됩니다
                ↓
3. 목록         내가 쓴 일지가 날짜 최신순으로 보입니다
                ↓
4. 상세         운동별 세트 표와 소계, 총 볼륨이 보입니다
                ↓
5. 수정 / 삭제  [수정]은 기존 값이 채워진 폼을 엽니다
                [삭제]는 한 번 더 확인을 거칩니다
```

**식단 기록** — 위쪽 `식단` 탭으로 이동합니다.

```
1. 식단 기록    날짜와 끼니(아침·점심·저녁·간식)를 고릅니다
                [+ 음식 추가]로 음식을 여러 개 넣습니다
                섭취량은 숫자와 단위(g / 인분)를 따로 입력합니다
                → 칼로리 합계가 즉시 갱신됩니다
                ↓
2. 목록         날짜별로 묶여서, 묶음마다 그날의 총 칼로리와
                탄·단·지 비율 막대가 붙습니다
```

> 칼로리는 **입력한 값을 그대로** 씁니다. 탄·단·지로 계산한 값은 "참고용" 힌트로만 보여주며 덮어쓰지 않습니다.

**대시보드** — 첫 화면입니다. 고른 날짜의 운동·식단·신체 기록을 한눈에 봅니다.

```
날짜 [2026-08-31]  ◀ ▶ [오늘]

┌── 운동 ───────────────┐ ┌── 식단 ────────────────┐
│ 등 + 이두 루틴  60분   │ │ [아침] 오트밀     420   │
│ 데드리프트    3,000kg  │ │ [점심] 닭가슴살   680   │
│ 랫풀다운      2,640kg  │ │ [저녁] 연어       740   │
│ 총 볼륨       5,640kg  │ │ 총 섭취  1,840 kcal     │
└────────────────────────┘ │ ███████░░░░░░░░         │
                           └─────────────────────────┘
── 칼로리 밸런스  [추정치] ─────────────────────────
   기초대사 1,688 + 운동 소모 360 − 섭취 1,840
   +208 kcal
```

> **칼로리 관련 수치는 모두 추정치입니다.**
> 기초대사량은 Mifflin-St Jeor 식으로, 운동 소모는 `MET 5.0 × 체중 × 시간`으로 계산합니다.
> 근력운동 강도를 상수 하나로 잡으므로 실제와 차이가 클 수 있습니다.
>
> **성별·출생연도·키·체중 중 하나라도 없으면 계산하지 않고** 무엇이 없는지 알려줍니다.
> 임의의 기본값으로 대신 계산하면 그럴듯하지만 틀린 숫자를 보여주게 되기 때문입니다.
>
> 그날의 체중 기록이 없으면 **그 이전의 가장 최근 기록**을 쓰고, 어느 날짜 값인지 화면에 함께 적습니다.

**내 몸 · 프로필** — `내 몸` 탭과 헤더의 이름을 클릭하면 열립니다.

```
내 몸    날짜 · 체중 · 컨디션 메모를 저장합니다
         같은 날짜로 저장하면 그날 기록을 덮어씁니다 (하루 1건)
         목록의 [불러오기]를 누르면 그 기록이 폼에 채워집니다

프로필   성별 · 출생연도 · 키를 저장합니다
         기초대사량 계산에 쓰이며, 비워두면 계산하지 않습니다
```

**루틴** — 자주 하는 구성을 저장해 두고 재사용합니다.

```
1. 루틴 만들기   이름과 운동 구성(무게·횟수 목표값)을 저장합니다
                 루틴은 계획이라 날짜와 완료 체크가 없습니다
                 ↓
2. 시작하기      [이 루틴으로 시작]을 누르면 그 구성으로 새 일지가 열립니다
                 완료 체크는 모두 해제된 상태입니다 (오늘은 아직 안 했으니까)
```

일지를 쓸 때 **[직전 기록 불러오기]** 를 누르면, 각 운동 이름과 **같은 이름의 가장 최근 기록**을 찾아 무게·횟수를 채웁니다. 완료 체크는 가져오지 않습니다.

**목록이 길어지면** — 운동·식단·내 몸 목록은 한 번에 전부 보여주지 않고 나눠서 보여줍니다.

```
              ⋮
   [ 일지 #16 ]
   ─────────────────────
        10 / 25건
        [ 더 보기 ]      ← 누르면 다음 10건이 아래에 이어집니다
```

- 목록 아래에 **지금까지 몇 건을 보고 있는지**(`10 / 25건`)가 표시됩니다.
- 마지막까지 불러오면 **버튼만 사라지고 개수는 남습니다.** 목록이 끝났다는 표시입니다.
- 기록이 한 페이지로 끝나면 이 영역은 아예 보이지 않습니다.
- 식단은 날짜별로 묶여 보이는데, 묶음이 페이지 경계에서 잘려도 **다음 페이지를 불러오면 같은 날짜끼리 알아서 합쳐집니다.**
- 대시보드는 **그날의 기록 전부**를 합산해야 정확하므로 나눠 받지 않습니다.

**알아두면 좋은 것**

- 새로고침(F5)해도 로그인이 유지됩니다. **며칠 뒤에 다시 와도 그대로입니다** (14일).
- 화면 오른쪽 위 **🌗 버튼**으로 밝기를 바꿉니다. 누를 때마다 `시스템 설정 따르기 → 밝게 → 어둡게` 순으로 돕니다.
- **작성 중에 다른 화면으로 가려 하면 확인을 받습니다.** "계속 작성"을 고르면 적던 내용이 그대로 남습니다.
- 비밀번호는 **프로필 화면**에서 바꿉니다. 바꾸면 **다른 기기의 로그인이 모두 풀립니다.**
- 다른 계정으로 로그인하면 **앞 계정의 일지는 보이지 않습니다.**
- **브라우저 뒤로/앞으로가기 버튼이 동작합니다.** 화면을 옮기면 주소도 `#/workouts/6a9593d7b4ebc171ed98a22c` 처럼 함께 바뀝니다.
- 그래서 특정 일지의 주소를 **복사해 두거나 북마크**할 수 있고, 새 탭에 붙여넣으면 그 일지가 바로 열립니다.
- 이미 지운 기록의 주소로 뒤로가기하면 **"이미 삭제된 일지입니다"** 라고 알려주고 목록으로 돌아갑니다.
- 서버를 껐다 켜도 **회원과 기록은 그대로 남아 있습니다.** MongoDB에 저장되기 때문입니다.

## 6. API를 직접 호출해보기

화면 없이 API만 확인하고 싶을 때입니다. 터미널을 **하나 더** 열고(서버는 켜둔 채로) 아래를 순서대로 실행합니다.

> Windows PowerShell에서는 `curl`이 다른 명령어로 연결되어 있습니다. `curl` 대신 **`curl.exe`** 라고 쓰세요.
> 더 편한 방법은 [7번 test.http](#7-testhttp로-테스트하기)입니다.

### ① 회원가입

```bash
curl -X POST http://localhost:3000/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"email":"demo@example.com","password":"password1234","name":"김헬스"}'
```

```json
{ "id": "6a9593d2b4ebc171ed98a22b", "email": "demo@example.com", "name": "김헬스" }
```

### ② 로그인 — 토큰 받기

```bash
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"demo@example.com","password":"password1234"}'
```

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpZCI6MSwiZW1haWwiOiJkZW1v...",
  "user": { "id": "6a9593d2b4ebc171ed98a22b", "email": "demo@example.com", "name": "김헬스" }
}
```

**`token` 값을 복사해 두세요.** 아래 요청부터 계속 씁니다.

### ③ 일지 쓰기

`<복사한_토큰>` 자리에 ②에서 받은 토큰을 붙여 넣습니다.


## 8. API 명세

기본 주소: `http://localhost:3000`

### 공통

- 요청 본문과 응답은 모두 JSON입니다. 본문을 보낼 때는 `Content-Type: application/json` 헤더가 필요합니다.
- 응답에 **비밀번호는 절대 포함되지 않습니다.**

### 공통 — 목록 나눠 받기 (페이지네이션)

일지·식단·루틴·신체지표의 **목록 조회는 모두 `?page=`와 `?limit=`을 붙일 수 있습니다.**
기록은 매일 쌓이므로, 목록을 부를 때마다 전부 받으면 나중에 느려집니다.

| 쿼리 | 뜻 | 기본값 |
|---|---|---|
| `page` | 몇 번째 묶음인지 (1부터) | `1` |
| `limit` | 한 묶음에 몇 개인지 (최대 100) | `20` |

```bash
GET /api/workouts?page=2&limit=10      # 11~20번째 일지
GET /api/meals?date=2026-08-30&page=1  # 날짜 필터와 함께 쓸 수 있습니다
```

**둘 다 생략하면 조건에 맞는 기록을 전부 돌려줍니다.** 대시보드처럼 "그날 것 전부"가 필요한 화면이 있어서 기존 동작을 그대로 남겨 두었습니다.

응답 **본문은 어느 경우든 배열**이고, 총 개수 같은 정보는 **응답 헤더**에 담습니다.

| 헤더 | 뜻 |
|---|---|
| `X-Total-Count` | 조건에 맞는 전체 개수 |
| `X-Total-Pages` | 전체 페이지 수 |
| `X-Page` · `X-Limit` | 지금 응답의 페이지 번호와 개수 |

`page=0`, `page=abc`, `limit=101`처럼 잘못된 값은 **400**으로 거절합니다. 슬쩍 1로 고쳐서 응답하면, 화면은 2페이지를 요청했다고 믿으면서 1페이지를 그리게 되기 때문입니다.

## 9. 인증(JWT)은 어떻게 동작하나요

로그인하면 **두 가지**를 받습니다. 역할과 보관 장소가 서로 다릅니다.

| | 액세스 토큰 | 갱신 토큰 |
|---|---|---|
| 하는 일 | 매 요청마다 "나는 누구다"를 증명 | 액세스 토큰을 새로 받아옴 |
| 수명 | **15분** | **14일** |
| 어디에 있나 | 응답 본문 → 브라우저 **메모리**(자바스크립트 변수) | **httpOnly 쿠키** |
| 화면에서 읽을 수 있나 | 읽을 수 있음 | **읽을 수 없음** |
| 서버에 저장되나 | 안 됨 (서명만 확인) | 됨 (해시로) |

```
로그인
  │
  ├─ 액세스 토큰 (15분) ──> 메모리에 보관. 요청마다 Authorization 헤더에 담아 보냄
  │
  └─ 갱신 토큰 (14일) ────> httpOnly 쿠키. 브라우저가 알아서 보관하고 붙여 보냄

15분 뒤 …
  요청 → 401 → 화면이 조용히 /api/auth/refresh 호출 → 새 액세스 토큰 → 요청 재시도
  (사용자는 아무것도 눈치채지 못합니다)
```

**왜 이렇게 나누나요**

`localStorage`에 토큰을 두면 이 사이트에서 도는 **모든 자바스크립트가 읽을 수 있습니다.** 남의 스크립트가 우리 페이지에서 실행되는 문제(XSS)가 한 번이라도 생기면 토큰이 통째로 새어 나갑니다.

`httpOnly` 쿠키는 자바스크립트가 **아예 읽을 수 없습니다.** 그래서 오래 사는 열쇠(갱신 토큰)를 여기에 두고, 짧게 사는 열쇠(액세스 토큰)만 메모리에 둡니다. 최악의 경우에도 새어 나가는 것은 15분짜리뿐입니다.

**새로고침하면 어떻게 되나요**

메모리에 있던 액세스 토큰은 사라집니다. 그래서 앱을 켤 때 항상 갱신을 한 번 시도합니다. 쿠키가 살아 있으면 조용히 로그인된 상태로 복구되고, 아니면 로그인 화면이 뜹니다.

**갱신 토큰은 한 번 쓰면 버려집니다 (회전)**

갱신할 때마다 서버가 옛 토큰을 지우고 새것을 심습니다. 같은 토큰을 14일 내내 쓰면 한 번 새어 나갔을 때 그 기간 내내 악용되지만, 회전시키면 훔친 토큰의 수명이 "다음 갱신까지"로 줄어듭니다.

**로그인이 풀리는 경우**

| 상황 | 결과 |
|---|---|
| 15분 지남 | 자동으로 갱신됩니다. 사용자는 모릅니다 |
| 14일 넘게 접속 안 함 | 다시 로그인해야 합니다 |
| 로그아웃 | 서버의 갱신 토큰도 지워집니다 |
| **비밀번호 변경** | **다른 기기의 로그인이 모두 풀립니다.** 바꾼 기기만 유지됩니다 |

비밀번호를 바꾸면 두 가지가 함께 일어납니다. 사용자의 **토큰 세대 번호**가 1 올라가서 그 전에 나간 액세스 토큰이 전부 거부되고, 저장된 **갱신 토큰도 모두 삭제**됩니다. 둘 중 하나만 하면 다른 기기가 남은 수단으로 계속 들어올 수 있습니다.

**CSRF는 어떻게 막나요**

쿠키를 쓰면 보통 CSRF(다른 사이트가 사용자의 쿠키를 이용해 몰래 요청을 보내는 것)를 걱정해야 합니다. 이 앱은 쿠키에 `SameSite=Lax`를 걸어 **다른 사이트에서 보낸 POST 요청에는 쿠키가 실리지 않게** 했습니다. 그래서 별도의 CSRF 토큰이 필요 없습니다.

**로그인 시도 횟수 제한**

같은 사람이 같은 계정에 **10분 안에 10번** 넘게 로그인을 시도하면 잠시 막습니다. 비밀번호를 자동으로 바꿔가며 시도하는 공격을 막기 위한 것입니다. 막히면 `429`와 함께 몇 초 뒤에 다시 오면 되는지 알려줍니다.

> 사람과 계정을 **함께** 묶어서 셉니다. 접속 위치만 세면 학교·회사처럼 여러 명이 같은 인터넷을 쓰는 곳에서 한 사람 때문에 모두가 잠기고, 계정만 세면 공격자가 계정을 바꿔가며 얼마든지 시도할 수 있기 때문입니다.

## 10. 에러 응답

에러는 항상 아래 형태입니다.

```json
{ "message": "무엇이 잘못됐는지" }
```

| 코드 | 언제 | 예시 메시지 |
|---|---|---|
| `400` | 값이 빠졌거나 형식이 틀림 | `date는 YYYY-MM-DD 형식이어야 합니다.` |
| `401` | 로그인 실패, 또는 토큰 문제 | `인증이 필요합니다.` |
| `404` | 일지가 없거나 **내 것이 아님**, 없는 경로 | `일지를 찾을 수 없습니다.` |
| `409` | 이미 가입된 이메일 | `이미 가입된 이메일입니다.` |
| `500` | 서버 내부 오류 | `서버 오류가 발생했습니다.` |

### 왜 남의 일지에 403이 아니라 404인가요

`403 Forbidden`("권한 없음")으로 응답하면 **"그 번호의 일지가 실제로 존재한다"**는 사실이 노출됩니다.
번호를 1부터 훑으면 다른 사람이 몇 개의 일지를 썼는지 알 수 있게 됩니다.
그래서 **없는 일지와 남의 일지를 똑같이 404로** 응답합니다.

같은 이유로 로그인 실패도 "없는 이메일"과 "틀린 비밀번호"를 구분하지 않고 동일한 메시지를 보냅니다.

## 12. 문제 해결 (FAQ)

### `MongoDB에 연결하지 못했습니다` 라고 뜨면서 서버가 안 켜져요

MongoDB가 실행 중이 아닙니다. 화면에 나온 확인 절차를 따라가면 됩니다.

```powershell
Get-Service MongoDB      # Running 이어야 합니다
Start-Service MongoDB    # 멈춰 있으면 시작
```

설치 자체가 안 되어 있다면 [3. 설치하기](#3-설치하기)를 참고하세요.

### `3000번 포트를 이미 다른 프로그램이 쓰고 있어...` 라고 뜨면서 서버가 안 켜져요

**가장 흔한 원인은 서버가 이미 다른 터미널에 켜져 있는 경우입니다.** 그 터미널에서 `Ctrl + C`로 끄면 됩니다.

그래도 안 되면 누가 쓰고 있는지 찾아 종료합니다.

```powershell
# Windows PowerShell
netstat -ano | findstr :3000
taskkill /PID <위에서_찾은_번호> /F
```

```bash
# macOS / Linux
lsof -ti:3000 | xargs kill -9
```

또는 `.env`에서 포트 번호만 바꿔도 됩니다.

```
PORT=3001
```

### `.env에 JWT_SECRET이 없습니다` 라고 뜨면서 서버가 안 켜져요

`.env` 파일이 없거나, 있어도 `JWT_SECRET=` 뒤가 비어 있는 경우입니다.

```powershell
Copy-Item .env.example .env    # .env가 아예 없다면
```

그 다음 `.env`를 열어 `JWT_SECRET`에 아무 문자열이나 채우고 서버를 다시 켜세요.

일부러 기본값을 두지 않았습니다. 기본 키가 코드에 적혀 있으면 그 키를 아는 사람이 "나는 아무개다"라고 적힌 토큰을 직접 만들어 낼 수 있기 때문입니다.

### `[MongoDB] 연결이 끊겼습니다` 가 뜨고 화면이 멈춰요

서버가 도는 중에 MongoDB가 꺼진 경우입니다. (윈도우 업데이트 후 재부팅 등)

```powershell
Start-Service MongoDB
```

다시 켜면 터미널에 `[MongoDB] 다시 연결되었습니다.` 가 찍히고 정상으로 돌아옵니다. **서버는 끄지 않아도 됩니다.** 알아서 재연결을 계속 시도합니다.

### 터미널에 요청이 한 줄씩 계속 찍혀요

정상입니다. `morgan`이 들어온 요청을 기록하는 것입니다.

```
POST /api/workouts 201 12.480 ms - 385
GET /api/workouts?page=1&limit=3 200 8.650 ms - 595
```

`경로 → 상태코드 → 걸린 시간 → 응답 크기` 순서이고, 상태 코드에 색이 붙습니다(2xx 초록 / 4xx 노랑 / 5xx 빨강). 화면을 새로고침하면 CSS·JS 같은 정적 파일 요청까지 함께 찍혀서 여러 줄이 올라옵니다.

API 요청만 보고 싶다면 `app.js`에서 `app.use(morgan('dev'))`를 `app.use('/api', morgan('dev'))`로 바꾸면 됩니다.

### 계속 401이 나와요

체크리스트입니다.

1. `Authorization` 헤더를 넣었나요?
2. `Bearer` 와 토큰 사이에 **공백 한 칸**이 있나요? (`Bearer<토큰>` ❌)
3. 토큰을 복사할 때 앞뒤 따옴표나 줄바꿈이 딸려 오지 않았나요?
4. 발급받은 지 **1시간이 지나지 않았나요?** 지났다면 다시 로그인하세요.

> 참고: 서버를 재시작해도 **401이 나지는 않습니다.** 데이터가 MongoDB에 남아 있고,
> 토큰도 `JWT_SECRET`이 그대로면 계속 유효하기 때문입니다.
> (`.env`의 `JWT_SECRET`을 바꾸고 재시작하면 그때는 기존 토큰이 전부 401이 됩니다.)

### 회원가입에서 409가 나와요

이미 그 이메일로 가입되어 있습니다. 다른 이메일을 쓰세요.

> 예전에는 서버를 재시작하면 회원이 사라졌지만, 이제는 MongoDB에 남아 있어 재시작으로는 지워지지 않습니다.

### 주소에 `#/` 가 붙어요

`http://localhost:3000/#/workouts/3` 처럼 보이는 게 정상입니다. `#` 뒤쪽은 **서버로 전송되지 않고** 브라우저 안에서만 쓰이기 때문에, 서버를 고치지 않고도 뒤로가기·북마크를 지원할 수 있습니다.

주소를 그대로 복사해 다른 탭에 붙여넣으면 같은 화면이 열립니다.

### 폼을 쓰다가 뒤로가기를 눌렀더니 입력한 게 날아갔어요

저장 전 내용은 보관하지 않습니다. 확인창을 띄우려면 별도 UI가 필요한데(해시 이동은 브라우저 기본 이탈 경고가 뜨지 않습니다) 폼이 짧아 넣지 않았습니다.

### 화면에서 "서버에 연결할 수 없습니다"가 떠요

서버가 꺼져 있습니다. 터미널에서 `npm run dev`로 다시 켠 뒤 화면을 새로고침하세요.

### 비밀번호를 바꿨더니 다른 기기에서 로그아웃됐어요

정상입니다. 비밀번호를 바꾸는 이유는 대개 남이 알게 됐기 때문이므로, 그 사람이 이미 로그인해 둔 것까지 끊어야 의미가 있습니다. 바꾼 기기에서는 그대로 로그인이 유지됩니다.

### `429 로그인 시도가 너무 많습니다`가 떠요

같은 계정에 10분 안에 10번 넘게 로그인을 시도했습니다. 응답에 적힌 시간만큼 기다리면 다시 됩니다. 개발 중에 자주 부딪힌다면 서버를 재시작해도 초기화됩니다(기록이 메모리에 있기 때문입니다).

### 로그인했더니 갑자기 로그아웃돼요

MongoDB로 옮기기 **전에 발급된 토큰**을 브라우저가 들고 있으면 그렇습니다. 예전 토큰은 사용자 번호가 숫자(`1`)인데 지금은 24자리 문자열이라, 서버가 유효하지 않은 토큰으로 보고 `401`을 돌려줍니다.

한 번 로그아웃되고 나면 정상입니다. 다시 로그인하면 됩니다.

### 화면을 고쳤는데 반영이 안 돼요

브라우저가 예전 CSS·JS를 캐시하고 있을 수 있습니다. **`Ctrl + Shift + R`** (강력 새로고침)을 누르세요. `public/` 안의 파일은 정적 파일이라 `nodemon`이 서버를 재시작해도 브라우저는 자동으로 다시 받지 않습니다.

### PowerShell에서 curl 명령이 이상하게 동작해요

PowerShell의 `curl`은 실제 curl이 아니라 `Invoke-WebRequest`의 별칭입니다. **`curl.exe`**라고 명시하거나, `test.http`를 사용하세요.

### 한글이 깨져 보여요

터미널 인코딩 문제일 뿐, 서버는 UTF-8로 정상 응답하고 있습니다. VS Code REST Client나 브라우저에서 보면 정상입니다.

### `req.body`가 `undefined`예요 (코드를 수정한 경우)

`app.js`에서 `app.use(express.json())`이 라우터 등록보다 **위에** 있는지 확인하세요.

## 배포할 때 (HTTPS와 프록시)

로컬에서 공부할 때는 신경 쓰지 않아도 됩니다. **다른 사람이 접속하는 곳에 올릴 때** 읽으세요.

### HTTPS는 이 서버가 직접 하지 않습니다

지금은 `http`로 통신합니다. 암호화가 없으므로 같은 공유기를 쓰는 사람이 **비밀번호와 토큰을 그대로 들여다볼 수 있습니다.** 실제 배포에서는 HTTPS가 반드시 필요합니다.

다만 그 일은 **이 서버가 직접 하지 않습니다.** 앞에 nginx나 Caddy 같은 프로그램을 세우고, 그것이 암호화를 처리한 뒤 뒤쪽 Node에는 평문으로 넘기는 것이 일반적입니다.

```
브라우저 ──HTTPS(암호화)──> nginx ──HTTP(평문)──> 이 서버(3000번)
                                   같은 컴퓨터 안이라 안전
```

Caddy를 쓰면 인증서 발급·갱신까지 자동입니다. 설정 파일은 이 두 줄이 전부입니다.

```
my-domain.com {
  reverse_proxy localhost:3000
}
```

> 로컬에서 직접 인증서를 만들어 붙이는 것은 권하지 않습니다. 브라우저가 "안전하지 않은 사이트" 경고를 띄우고, 그 경고를 넘기는 방법만 익히게 됩니다. 게다가 브라우저는 `localhost`를 이미 안전한 곳으로 취급합니다.

### 코드에 필요한 것은 두 줄입니다

**① `app.set('trust proxy', 1)`** — `app.js`에 이미 들어 있습니다.

프록시 뒤에 서면 모든 요청이 프록시에서 오는 것처럼 보여, `req.ip`가 전부 같은 값이 됩니다. 이 설정이 없으면 **로그인 시도 횟수 제한이 전체 사용자를 한 사람으로 취급**해서, 누군가 5번 틀리면 모두가 함께 잠깁니다.

**② 쿠키의 `Secure` 플래그** — `NODE_ENV=production`일 때 자동으로 켜집니다.

켜면 그 쿠키는 HTTPS에서만 전송됩니다. 로컬은 `http`라서 켜면 로그인이 아예 안 되므로, 환경에 따라 갈립니다. 배포할 때 이 환경 변수를 잊지 마세요.

```bash
NODE_ENV=production npm start
```

## 기존 데이터 정리 (이메일 대소문자)

이 버전부터 이메일을 **소문자로 정규화**해서 저장합니다.
`User@example.com`과 `user@example.com`이 서로 다른 계정이 되던 문제를 막기 위해서입니다.

**이전 버전에서 만든 데이터가 있다면 한 번만** 아래를 실행해 기존 이메일을 소문자로 맞춰 주세요.
그러지 않으면 대문자가 섞인 계정은 로그인 시 조회되지 않습니다.

```powershell
# 먼저 대문자가 섞인 계정이 있는지 확인
mongosh workout-log --eval "db.users.find({ email: /[A-Z]/ }, { email: 1 }).toArray()"
```

바꿀 대상이 있다면:

```powershell
mongosh workout-log --eval "db.users.find({ email: /[A-Z]/ }).forEach(u => db.users.updateOne({ _id: u._id }, { \$set: { email: u.email.toLowerCase().trim() } }))"
```

> **먼저 확인부터 하세요.** 소문자로 바꿨을 때 이미 있는 계정과 겹치면
> unique 인덱스에 걸려 그 한 건만 실패합니다(나머지는 정상 처리됩니다).
> 그런 경우 두 계정 중 어느 쪽을 남길지 직접 정해야 합니다.
>
> 새로 시작하는 경우에는 할 일이 없습니다.

## 주의사항

학습용 프로젝트이므로 실제 서비스에 그대로 쓰기에는 다음이 부족합니다.

- **비밀번호 재설정이 없습니다.** 비밀번호를 잊으면 스스로 되찾을 방법이 없습니다 (본인 확인용 이메일 발송이 필요하기 때문입니다)
- 로그인 시도 제한이 **서버 메모리**에 있습니다. 서버를 재시작하면 초기화되고, 서버를 여러 대로 늘리면 각자 따로 셉니다. 실제 서비스는 Redis 같은 공용 저장소가 필요합니다
  - 특히 **Vercel 같은 서버리스에 배포하면 사실상 작동하지 않습니다.** 요청마다 다른 인스턴스가 처리할 수 있어 횟수가 모이지 않기 때문입니다. 배포 환경에서 실제 방어가 필요하면 Upstash Redis 등으로 저장소를 옮겨야 합니다
- 접근 권한이 한 종류뿐입니다. 관리자 같은 역할 구분이 없습니다
- 파일 업로드(운동 사진 등)를 지원하지 않습니다
